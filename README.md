# Loan Ledger: LMS

Loan management system with the M2P book migrated as of **30 Apr 2026** and a new
payment waterfall for everything after it. FastAPI + MySQL backend, React admin UI,
packaged as one Docker container for AWS.

## What it does

- **Products** set the schedule type, waterfall, late fee, bounce charge, foreclosure and processing fee.
- **Booking**: reducing-balance EMI or flat-rate schedules, broken-period interest (ACT/365) when the
  first EMI date isn't one month after disbursal, month-end dates that don't drift.
- **Payments** go through the waterfall, with a live preview of the split before posting.
  Back-dated payments, reversals and bounces are exact: the loan is replayed from the start.
- **Charges**: manual charges, late fees by an end-of-day job (once per EMI, after grace days),
  bounce charge on reversal, admin waivers.
- **Foreclosure** quote and closure: overdue dues + principal not yet due + interest for the broken
  days + charges + foreclosure fee, less any excess held. Any surplus shows as refund due.
- **DPD / ageing**: Current, SMA-0, SMA-1, SMA-2, NPA (90+), on the loan and the portfolio.
- **M2P migration** from CSV exports, with a dry run, row-level errors and receipt reconciliation.
- **Users and audit**: ADMIN / OPS / VIEWER roles, JWT sign-in, every posting written to `audit_log`.

## The waterfall (new apportionment logic)

Default is **Interest → Principal → Charges**, oldest first, and only for amounts already due on
the payment date.

| Setting | Options |
|---|---|
| `apportion_mode` | `HEAD_WISE` (default): all overdue interest across EMIs, then all overdue principal, then charges. `INSTALLMENT_WISE`: oldest EMI's interest then principal, then the next EMI, charges last. |
| `excess_mode` | `HOLD` (default): money left over is held and adjusted automatically on the next due date. `ADVANCE`: applied to future EMIs immediately. |

It's set per product and copied to the loan at booking, so changing a product never re-writes
existing loans. The engine is `backend/app/engine/apportion.py`; the rule that keeps it exact is in
`services/loan_service.py::replay`: instalment "paid" amounts are never edited by hand. They are
rebuilt from the opening (migrated) amounts by re-applying every live payment in date order.

## M2P migration

Export four CSVs from M2P (`backend/sample_data/m2p/` has the exact format, generated by
`scripts/make_sample_m2p.py`):

| File | Required | Holds |
|---|---|---|
| loans.csv | yes | loan master with customer details |
| schedule.csv | yes | every instalment with **principal and interest paid as on the cutoff** |
| receipts.csv | no | receipt history; used for reconciliation |
| charges.csv | no | charges with paid and waived amounts as on the cutoff |

How it is treated:
- Each M2P loan comes in exactly as M2P had appropriated it on the cutoff. Those amounts are the
  loan's opening position; the new waterfall never re-splits pre-cutoff money.
- Receipts on or before the cutoff are stored as history. Receipts **after** the cutoff found in the
  export are posted through the new waterfall.
- Payments dated on or before the cutoff can't be posted to a migrated loan.
- Reconciliation compares receipts till cutoff with what M2P appropriated; differences over ₹1 are flagged.
- Header names are matched loosely (LAN, Loan No, ROI, EMI Due Date, UTR …). Add any unknown header to
  `ALIASES` in `backend/app/services/m2p_import.py`.

In the app: **M2P migration & EOD → choose files → Check files** (nothing saved) **→ Import loans**.
Loans with errors are skipped; re-importing a loan is refused.

## Run locally

### Windows (Docker Desktop)

1. Install [Docker Desktop](https://www.docker.com/products/docker-desktop) and start it.
2. In PowerShell, from the project folder:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
   ```

   This creates `.env` with generated passwords (first run only), builds the app and starts MySQL and the app.
3. Open http://localhost:8000 and sign in as `admin`. The password is `ADMIN_PASSWORD` in `.env`.

To stop: `docker compose down`. To start again: run `setup.ps1` again (it keeps your data).

### Mac or Linux

Docker: `./scripts/setup.sh` (same as Windows).

Without Docker, on a Mac: `./start-local.sh` (uses MySQL if installed, otherwise SQLite) or double-click `Run LMS.command`.
It loads demo data on first run and opens http://localhost:8000 (admin / Admin@12345). `--sqlite` forces SQLite, `--reset` starts fresh.

### Without Docker (any OS)

`pip install -r backend/requirements.txt`, run `uvicorn app.main:app` from `backend/` with `DATABASE_URL` set,
and `npm run dev` in `frontend/` (proxies `/api` to port 8000).

## Tests

```powershell
powershell -ExecutionPolicy Bypass -File scripts\test.ps1    # Windows
```
```bash
./scripts/test.sh                                              # Mac / Linux
```

Both install the packages, run the backend tests (`backend/tests`, engine and API) and build the frontend.
GitHub Actions runs the same backend tests, the frontend build and a Docker build on every push and pull request
(`.github/workflows/ci.yml`).

### Reference checks (real loans)

`backend/tests/reference/` checks figures that were signed off against the migrated database, for example
loan GFLE2W100009242 (FCL 69,131, charges 4,200 (unpaid late charges), total 73,331 and DPD 65 as of 8 Nov 2026; DPD 26 as of 30 Apr 2026).
These need that database, so they are skipped unless you point them at it. Keep the database URL and password
in environment variables, not in files:

```bash
cd backend
REFERENCE_DATABASE_URL='mysql+pymysql://user:password@127.0.0.1:3307/GFL_DWH'  # AWS RDS via the SSH tunnel REFERENCE_ADMIN_PASSWORD='...' \
  python -m pytest tests/reference -v
```

They are not run in CI, because CI has no access to the customer database.

## Keeping secrets and customer data out of git

- `.gitignore` excludes `.env` (except `.env.example`), `*.pem`, `*.key`, `.local/` (local database), `venv`,
  `node_modules`, build output, and `backend/sample_data/loan_master/` (real customer details).
- Never commit passwords, database URLs or customer files. Production secrets go in AWS Secrets Manager.
- Before the first push to any remote, check with `git status` and `git ls-files` that no `.env`, `.pem`, `.db`
  or customer CSV is tracked.

## Deploying on AWS

The app is one stateless container; MySQL holds all state.

1. **RDS for MySQL 8** (Multi-AZ for production) in private subnets, `ap-south-1`. Create database
   `lms` (`backend/db/schema_mysql.sql`, or let the app create tables on first start) and an app user.
2. **ECR**: build and push the image from the repo root (`docker build -t lms .`).
3. **ECS Fargate** service (or a single EC2 with Docker) behind an **Application Load Balancer** with an
   ACM certificate. Run 2 tasks. Put `DATABASE_URL`, `JWT_SECRET`, `ADMIN_PASSWORD` in **Secrets Manager**
   and reference them in the task definition. Health check path `/api/health`.
4. **End of day**: an **EventBridge Scheduler** rule that runs the same task definition daily at
   00:30 IST with the command `python -m app.cli late-fees`.
5. Security group: RDS accepts 3306 only from the ECS tasks. Turn on RDS automated backups and
   Performance Insights. Sign in once, then change the admin password by creating a new admin user.

## Assumptions to confirm

- Cutoff is 30 Apr 2026, and M2P's own split of pre-cutoff money stands.
- Monthly EMIs only. Interest isn't charged on overdue amounts beyond the schedule (penal charges are
  flat late fees, in line with RBI's 2024 penal-charges rules). GST on fees isn't added.
- Processing fee is recorded on the loan, assumed deducted at disbursal, not collected through EMIs.
- A foreclosure payment can't be reversed from the screen.
- The portfolio report computes ageing in the app; past roughly 50,000 active loans it should move to
  a nightly snapshot table.
